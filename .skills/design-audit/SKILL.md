# Аудит макета

1. Открой [входной бриф](../../input/HANDOFF_FROM_RESEARCH.md), целевые фреймы и релевантные правила из [карты](../../index.md). Сверь сценарии и критерии из брифа с деревом узлов и видом макета.
2. Проверь все затронутые фреймы на соответствие следующим критериям.

| Критерий | Проверка |
| --- | --- |
| Структура | Имена слоёв, Auto Layout, корректный Hug/Fill/Fixed и отсутствие случайного переполнения. |
| Компоненты | Библиотечные экземпляры, нужные варианты, сохранённые связи и соответствие Code Connect при наличии. |
| Токены | [Семантические Variables](../../rules/tokens-summary.md) и режимы, Text Styles, управляемые свойства без сырых значений. Прямая привязка `font/family` к тексту — отклонение. Кегль 32 px из [стиля `Health/Display/Metric-2`](../../rules/figma-styles.md#text-styles) допустим без отдельной Variable. Для отступов используй [сетку Auto Layout](../../rules/figma-discipline.md#сетка-отступов-auto-layout). |
| UX | Основное действие, понятные тексты и состояния. Пройди [10 эвристик Нильсена](../../rules/ux-heuristics.md#10-эвристик-нильсена) по ключевому сценарию и проверь [лимиты композиции](../../rules/ux-heuristics.md#плотность-и-ритм). Для «Здоровья» сверяйся с [паттернами экранов](../../rules/ux-patterns.md) и [антитревожностью](../../rules/ux-heuristics.md#антитревожность). |
| Доступность | Контраст в каждом целевом режиме, видимый фокус, логичный порядок обхода, размеры зон тапа и статус помимо цвета. |
| Адаптация | Крайние целевые размеры, длинные строки, реальные данные и изменение высоты контейнеров. Для «Здоровья» проверь базовый размер `402 × 874` и минимальный вьюпорт `375 × 812`. |

3. Запиши каждое отклонение с прямой ссылкой на узел, наблюдением, ожидаемым результатом и статусом. Отметь отдельно проверки, для которых не хватило данных. Зафиксируй блокеры передачи, если затронут основной сценарий, доступность или обязательная привязка.
4. Исправь отклонения в пределах задачи и перепроверь затронутые фреймы.

## Передача в разработку

1. Заполни [output/SPECS_FOR_DEV.md](../../output/SPECS_FOR_DEV.md). Сопоставь каждый критерий брифа с проверенным фреймом, ожидаемым поведением и статусом. Включи компоненты, варианты, адаптацию, режимы темы, открытые отклонения и блокеры. Подтверждённые старые привязки `space/4` и `space/8` запиши как неблокирующее наследие со значениями `4px` и `8px` по [правилам сетки](../../rules/figma-discipline.md#сетка-отступов-auto-layout).
2. Скомпилируй [output/figma-tokens.json](../../output/figma-tokens.json) в DTCG 2025.10. Из подтверждённых привязок собери токены для реализации и их транзитивные зависимости. Только на этом шаге выбирай нужные ветки из `rules/tokens-dtcg.json` JSON-фильтром. Сохраняй пути, типы, единицы, алиасы и ветки `color.light` и `color.dark` для целевых режимов. Общие размеры записывай один раз. Старые привязки отступов вне активной коллекции фиксируй в спецификации и исключай из JSON.
3. Проверь корректность JSON, разрешение ссылок на токены и наличие всех заявленных режимов. Если отсутствует обязательная роль или остаётся конфликт с Figma, зафиксируй в спецификации узел, режим и недостающее значение.
4. Запиши в оба файла ID и ревизию входного брифа. В JSON используй поля `briefId` и `briefRevision` в `$extensions["com.design-harness.handoff"]`. После проверок поставь согласованный статус. «Готово к передаче» соответствует `ready`, «Заблокировано» соответствует `blocked`. Блокеры опиши в спецификации.

## Проверки реализации

Для применимых проверок укажи условия Stylelint по сырым значениям и сценарии Playwright по размерам, состояниям и визуальным регрессиям. Добавь проверки доступности, в том числе ручные проверки фокуса и порядка обхода. Отметь фактический статус каждой проверки.
