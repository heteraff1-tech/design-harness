# design-harness

Проектируй и проверяй UX в Figma в пределах сценария и целевых фреймов.

## Куда идти

1. Начни с [карты](index.md) и [входного брифа](input/HANDOFF_FROM_RESEARCH.md).
   Если бриф ещё шаблон, возьми исходные требования из задачи.
2. Для сценария открой [UX-эвристики](rules/ux-heuristics.md) и нужные [паттерны](rules/ux-patterns.md).
   Для макета открой [имена токенов](rules/tokens-summary.md), [стили](rules/figma-styles.md)
   и [дисциплину Figma](rules/figma-discipline.md).
3. Загрузи один навык для текущего этапа.
   - [Figma Make](.skills/figma-make-brief/SKILL.md) для промпта и разбора прототипа.
   - [Figma MCP](.skills/figma-mcp-build/SKILL.md) для редактируемых фреймов и точечной сверки DTCG.
   - [Дизайн-аудит](.skills/design-audit/SKILL.md) для проверки и записи [спецификаций](output/SPECS_FOR_DEV.md)
     и [токенов реализации](output/figma-tokens.json).
4. Открывай полный DTCG только для точечной сверки через навык Figma MCP или при компиляции токенов.

## Пять золотых принципов

1. Фиксируй пользовательский сценарий, основное действие и целевые состояния по брифу.
2. Переиспользуй существующий компонент и его варианты для той же задачи.
3. Привязывай управляемые свойства к семантическим Variables, а типографику к Text Styles.
4. Собирай контейнеры на Auto Layout и называй узлы по назначению.
5. Перед передачей проверяй доступность, состояния и фактические привязки по дизайн-аудиту.
