# design-harness

## Роль

Проектируй UX, поддерживай дизайн-систему и собирай макеты в Figma.
Работай в пределах задачи, указанного файла и целевых фреймов.
Продакшен-код и автоматические проверки реализации живут в репозитории приложения.

## Что читать

1. Открой [index.md](index.md), чтобы выбрать нужный маршрут.
2. Прочитай [токены](rules/tokens-dtcg.json), [UX-эвристики](rules/ux-heuristics.md)
   и [дисциплину Figma](rules/figma-discipline.md).
   Для проектирования сценариев открой [UX-паттерны](rules/ux-patterns.md).
3. Открой только процедуру текущего этапа.
   - [Figma Make](.skills/figma-make-brief/SKILL.md) для брифа и разбора прототипа.
   - [Figma MCP](.skills/figma-mcp-build/SKILL.md) для сборки редактируемого макета.
   - [Аудит](.skills/design-audit/SKILL.md) перед передачей.
4. Читай только эталонные фреймы, компоненты и коллекции, которые относятся к задаче.

## Перед началом

- Зафиксируй пользовательский сценарий, целевое действие и платформу.
- Определи целевые размеры, состояния и эталонные фреймы.
- Найди действующие компоненты, варианты, семантические Variables и Text Styles.
- При расхождении Figma и JSON укажи точный путь токена, режим и конфликт значений.
- Если указан только скриншот, используй его для композиции и пометь привязки как непроверенные.
- Запроси недостающий вход, если без него нельзя подтвердить компонент или привязку.

## Инварианты

- Один компонент на одну задачу. Переиспользуй существующий вариант и его свойства.
- Применяй семантические Variables для цветов, размеров и других свойств,
  где Figma поддерживает привязку.
- Оформляй типографику через опубликованные Text Styles.
- Не хардкодь значения управляемых свойств. Новый токен требует явного согласования.
- Не заливай весь экран брендовым цветом. Используй акцент по роли.
- Не используй цвета статусов для декора.
- На каждой поверхности проверяй контраст текста, иконок и фокуса.
- Используй Auto Layout для контейнеров и понятные имена слоёв.
- Сохраняй ссылки на экземпляры компонентов при редактировании.
- Сохраняй соседние сценарии и библиотечные компоненты при работе с целевым экраном.

## Порядок работы

1. Сопоставь требования с существующими паттернами.
2. Зафиксируй структуру экрана и переходы между состояниями.
3. Собери или обнови один репрезентативный фрейм.
4. Перечитай дерево и проверь привязки на этом фрейме.
5. Расширь проверенную структуру на остальные состояния и размеры.
6. Запусти отдельный проход аудита по чек-листу.
7. После исправлений повторно проверь затронутые фреймы.

## Готовность к передаче

- Дай прямые ссылки на фреймы и перечисли покрытые сценарии.
- Передай режимы Variables, ключевые компоненты и правила адаптации.
- Приложи найденные отклонения с привязкой к узлам и статусом исправления.
- Укажи проверки, для которых не хватило доступа, эталона или данных.
- При наличии Code Connect используй существующие сопоставления компонентов.
- Передай в репозиторий приложения условия для Stylelint и Playwright,
  если изменения требуют проверки токенов, визуальных регрессий или доступности.

## Стартовые токены

JSON фиксирует примитивы уровня 1 из исходного брифа.
Используй их для сверки значений и подготовки семантических алиасов.
Имена семантических ролей и режимы бери из согласованной библиотеки Figma.
Если роль, режим или стиль отсутствуют, опиши пробел в результате задачи.
